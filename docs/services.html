Services and infrastructure

Databases, cache, search, mail and storage run beside your applications as native processes, and the infrastructure canvas wires them in.

The infrastructure canvas

An application's Infrastructure tab draws its services as a canvas: PHP, its databases, cache, mail, search, storage and processes, joined to the application.

Add a database and Phun asks which engine: MySQL, MariaDB, PostgreSQL, SQLite or MongoDB. Add MySQL (or whichever you pick) installs and starts it, writes the settings and creates the database; Install only leaves your settings alone. An application can use more than one database; each gets a card with the connection name to use.

Phun only offers the services an application can use, and writes them where its framework reads them:

  • Laravel: .env.
  • Symfony: .env.local, one DSN each, such as DATABASE_URL and MAILER_DSN.
  • CodeIgniter: its own .env settings for databases, Redis, Memcached and mail.
  • WordPress: wp-config.php, MySQL or MariaDB, and Redis for the Redis Object Cache plugin.

An HTML application gets no services. One Phun cannot wire yet, such as CakePHP, Slim or plain PHP, is told so instead of being offered settings it would ignore.

A shared service's card on the canvas offers what belongs to the application: its logs, the database browser, Global Config and Remove. Starting, stopping, ports and versions live on the Services page, since they affect every application.

Processes

For Laravel, the canvas runs queue workers (as many as you need, each with its own queues and log), the scheduler and Reverb. Symfony gets Messenger workers. WordPress, CodeIgniter, Drupal and Magento get scheduled tasks, which run the application's own cron command every minute.

phun queue enable blog
phun schedule enable blog
phun messenger enable shop

The Services page

Services, on the Overview, lists every service Phun can run, installed or not, with Install or Update in its row. They run natively, started with Phun: no Docker, no virtual machine.

  • Databases: MySQL, MariaDB, PostgreSQL and MongoDB.
  • Cache: Redis and Memcached.
  • Search: Meilisearch, Typesense and OpenSearch.
  • Live updates: Mercure.
phun services
phun service install redis <version>
phun service set-port mysql 3307

Mail

Every email your applications send is caught and readable in the Mail viewer (Ctrl+5): rendered, as plain text or as the raw source. Nothing leaves your machine.

S3-compatible storage

Object storage on your machine, with public or private buckets and a browser for what is in them. Added to a Laravel application from the canvas, Phun creates its bucket and fills in its settings, so the s3 disk works as it would against S3.

Databases, browsed

A database card opens the database browser: one grid for any table, and SQL that completes tables and columns, for MySQL, MariaDB and PostgreSQL. For Laravel, Open Schema draws the tables and model relationships as blueprints; drag one model onto another to relate them, and review the change to each model before it is written.

Developer tools

Composer, Node.js, Bun, the Laravel installer, WP-CLI and Chrome for Testing install when you need them, without a system package manager.

phun tools
phun install tool node

Laravel Cloud

From a Laravel application's Infrastructure › Laravel Cloud, sign in with an API token, link it to a Cloud application, see what Cloud is missing compared with Phun, create it after confirming what Cloud bills for, and deploy. Phun keeps no copy of your token.
